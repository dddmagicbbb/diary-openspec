# Design

## Context

저장소에는 아직 애플리케이션 코드가 없다. OpenSpec 설정 파일과 스킬만 있다. 동기는 proposal.md의 Why를, 동작은 `specs/diary-entries/spec.md`를 따른다.

제약: 빌드 도구 없이 브라우저에서 파일을 바로 열어 동작해야 하며, 스택은 Vanilla JS + Tailwind + localStorage로 정해져 있다.

## Goals / Non-Goals

**Goals:**
- `index.html`을 더블클릭해 `file://`로 열어도 동작한다(로컬 서버 불필요).
- 저장 형식을 이후 수정·삭제 change에서 그대로 쓸 수 있게 잡는다.

**Non-Goals:**
- 자동화된 테스트 도구 도입. 이번에는 브라우저에서 시나리오를 직접 확인한다.
- 날짜 경계(자정)를 넘겨 페이지를 열어 둘 때 상단 날짜 자동 갱신. 새로고침하면 바뀐다.

## Decisions

### 파일 구성: `index.html` + `app.js`
- 마크업과 Tailwind 클래스는 `index.html`, 동작은 `app.js`(일반 `<script src>`, `defer`).
- 대안: 한 파일에 모두 넣기 → 짧지만 다음 change에서 로직을 고칠 때 diff가 마크업과 섞인다.
- 대안: ES module(`type="module"`) → `file://`에서 일부 브라우저가 CORS로 막는다. 쓰지 않는다.

### Tailwind: Play CDN 스크립트
- `<script src="https://cdn.tailwindcss.com">`로 불러온다. 빌드 단계가 없다는 제약에 맞는다.
- 대안: Tailwind CLI 빌드 → 결과 CSS가 가볍고 오프라인에서도 되지만 Node 빌드 단계가 생긴다. 지금 규모에선 과하다.
- 트레이드오프는 아래 Risks 참고.

### 저장 형식: 키 하나에 JSON 배열
- localStorage 키 `oneline-diary.entries`에 배열을 저장한다.
  ```json
  [
    { "id": "1798700700000-k3x9", "text": "한 해 마무리", "createdAt": "2026-12-31T14:05:00+09:00" }
  ]
  ```
- `createdAt`은 로컬 시간대 오프셋을 포함한 ISO 문자열로 저장한다. 표시용 날짜·시각을 다시 계산하지 않고 문자열에서 그대로 읽을 수 있고, UTC 변환으로 날짜가 밀리는 문제를 피한다.
- `id`는 저장 시각(ms) + 짧은 난수. 이번엔 쓰지 않지만 다음 수정·삭제 change에서 항목을 가리키는 데 필요하므로 지금 넣어 둔다.
- 배열은 저장 순서(오래된 것 먼저)로 두고, 화면에 그릴 때 뒤집어 최신순으로 보여준다.
- 대안: 기록마다 키를 따로 쓰기(`entry:<id>`) → 목록을 만들려면 전체 키를 훑어야 해서 번거롭다.
- 대안: 날짜를 키로 묶기(`{ "2026-12-31": [...] }`) → 하루 여러 개를 허용하므로 이득이 적고 정렬이 복잡해진다.

### 날짜·시각 포맷
- `Date`의 로컬 getter(`getFullYear`, `getMonth`, `getDate`, `getHours`, `getMinutes`)로 직접 조합하고 두 자리로 채운다.
- 대안: `toISOString()` → UTC라서 한국 기준 오전 9시 전에 날짜가 하루 전으로 나온다. 쓰지 않는다.
- 대안: `toLocaleDateString` → 로케일마다 형식이 달라 `YYYY-MM-DD`를 보장하지 않는다.

### 렌더링: 매번 목록 전체 다시 그리기
- 저장할 때마다 목록 요소를 비우고 전체를 다시 만든다. 항목은 `textContent`로 넣어 HTML로 해석되지 않게 한다(spec의 HTML 시나리오).
- 대안: 새 항목만 앞에 끼워 넣기 → 조금 빠르지만 빈 목록 안내 문구 처리 등 분기가 늘어난다. 한 줄 다이어리 규모에서 전체 다시 그리기는 충분히 빠르다.

### 입력 처리
- `<input maxlength="100">`로 길이를 막는다.
- 입력과 버튼을 `<form>`으로 감싸 `submit` 하나로 버튼 클릭과 Enter를 같이 처리한다.
- 한글 조합 중 Enter: `keydown`에서 `event.isComposing`이 참이면 `preventDefault()`로 제출을 막는다.
- 저장 후 입력칸을 비우고 다시 포커스를 준다.
- 빈 입력 경고는 브라우저 기본 `alert("내용을 입력해주세요.")`로 띄우고, 닫힌 뒤 입력칸에 포커스를 준다.
  - 대안: 입력칸 아래 인라인 경고 문구 → 화면 흐름을 끊지 않지만 표시·숨김 상태 관리가 생긴다. 지금은 가장 단순한 `alert`로 하고, 거슬리면 다음 change에서 바꾼다.
  - 대안: `<input required>`의 브라우저 기본 검증 말풍선 → 공백만 입력한 경우를 잡지 못하고 문구도 브라우저마다 달라 쓰지 않는다.

### 목록 스크롤
- 목록 컨테이너에 한 줄 항목 5개 분량의 최대 높이와 `overflow-y-auto`를 준다.
- 긴 내용은 말줄임으로 자르지 않고 줄바꿈해서 모두 보여준다. 그래서 긴 항목이 있으면 한 화면에 5개보다 적게 보일 수 있다.

## Risks / Trade-offs

- [Tailwind Play CDN은 운영용이 아니라고 공식 문서가 안내함, 인터넷 연결 필요] → 개인용 한 줄 다이어리라 수용. 오프라인 사용이 필요해지면 CLI 빌드로 바꾸는 별도 change를 연다.
- [localStorage는 브라우저·기기별로 따로이고, 사용자가 사이트 데이터를 지우면 기록이 사라짐] → 이번 범위에서 수용. 내보내기·백업은 이후 change 후보.
- [`file://`로 열면 브라우저에 따라 localStorage가 파일 경로별로 나뉘거나 막힐 수 있음] → 저장 실패 시 예외를 잡아 화면이 깨지지 않게 하고, 필요하면 간단한 로컬 서버(`npx serve` 등)로 여는 방법을 README에 적는다.
- [localStorage에 손상된 JSON이 있으면 파싱 오류] → `try/catch`로 감싸고 빈 배열로 시작한다(spec의 손상 시나리오). 손상된 원본은 덮어쓰기 전까지 그대로 둔다.
- [항목 내용이 길면 줄바꿈으로 높이가 달라져 "정확히 5개"가 안 보일 수 있음] → spec이 "5개 정도"로 정의하므로 수용.
