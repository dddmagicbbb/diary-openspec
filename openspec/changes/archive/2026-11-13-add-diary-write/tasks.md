# Tasks

## 1. 페이지 뼈대

- [x] 1.1 `index.html`을 만들고 Tailwind Play CDN 스크립트와 `app.js`(`defer`)를 불러온다. 날짜 표시 영역, `<form>` 안의 입력칸(`maxlength="100"`)과 저장 버튼, 목록 영역을 배치한다. 검증: 파일을 브라우저로 열면 Tailwind 스타일이 적용된 세 영역이 보이고 콘솔 오류가 없다.
- [x] 1.2 빈 `app.js`를 만든다. 검증: 개발자 도구 Network 탭에서 `app.js`가 200(또는 `file://` 로드 성공)으로 불러와진다.

## 2. 오늘 날짜 표시

- [x] 2.1 로컬 getter로 `YYYY-MM-DD` 문자열을 만드는 포맷 함수와 `YYYY-MM-DD HH:mm` 포맷 함수를 만들고, 페이지 로드 시 날짜 영역에 오늘 날짜를 넣는다. 검증: 페이지에 오늘 날짜가 `YYYY-MM-DD`로 보이고, 콘솔에서 `new Date(2026, 2, 5)`를 넣으면 `2026-03-05`, `new Date(2026, 11, 31, 14, 5)`를 넣으면 `2026-12-31 14:05`가 나온다.
- [x] 2.2 PC 시간대를 UTC+9로 두고 오전 9시 전(또는 개발자 도구 Sensors에서 시간대 변경)에 확인한다. 검증: UTC 날짜가 아닌 로컬 날짜가 표시된다.

## 3. 저장소(localStorage)

- [x] 3.1 키 `oneline-diary.entries`에서 기록 배열을 읽는 함수를 만든다. 값이 없거나 JSON 파싱에 실패하거나 배열이 아니면 빈 배열을 돌려준다. 검증: 콘솔에서 `localStorage.setItem('oneline-diary.entries', '{망가짐')` 후 새로고침해도 오류 없이 빈 상태로 열린다.
- [x] 3.2 기록 배열을 저장하는 함수를 만든다. `setItem`이 예외를 던지면 잡아서 화면이 깨지지 않게 한다. 검증: 저장 후 콘솔에서 `localStorage.getItem('oneline-diary.entries')`에 design.md의 형식(`id`, `text`, `createdAt`)으로 들어 있다.

## 4. 기록 저장

- [x] 4.1 `form`의 `submit`을 처리해 입력값을 trim하고, 비어 있으면 `alert("내용을 입력해주세요.")`를 띄운 뒤 입력칸에 포커스를 주고 끝낸다. 아니면 `id`·`text`·`createdAt`(로컬 오프셋 포함 ISO)을 만들어 배열 끝에 추가하고 저장한다. 저장 후 입력칸을 비우고 포커스를 준다. 검증: 버튼 클릭과 Enter 모두로 저장되고, 빈칸·공백만 입력하고 버튼이나 Enter를 누르면 경고 알림이 뜨고 저장되지 않으며 알림을 닫으면 입력칸에 커서가 있다. "  책 읽음  "은 "책 읽음"으로 저장된다.
- [x] 4.2 입력칸 `keydown`에서 `event.isComposing`이 참이면 제출을 막는다. 검증: 한글 "산책"을 입력하고 조합이 끝나기 전 Enter를 누르면 저장되지 않고, 한 번 더 Enter를 누르면 "산책"이 한 번만 저장된다.
- [x] 4.3 같은 날 두 번 저장한다. 검증: 기록이 두 개 남고 각각 저장 시각이 다르다.

## 5. 목록 표시

- [x] 5.1 기록 배열을 뒤집어 최신순으로 목록을 다시 그린다. 각 항목에 `YYYY-MM-DD HH:mm`과 내용을 `textContent`로 넣는다. 기록이 없으면 "아직 기록이 없어요" 안내를 보여준다. 페이지 로드와 저장 직후에 호출한다. 검증: "첫째", "둘째", "셋째" 순으로 저장하면 위에서부터 셋째·둘째·첫째로 보이고, `<b>굵게</b>`는 글자 그대로 보이며, 새로고침해도 같은 순서로 남는다.
- [x] 5.2 목록 컨테이너에 한 줄 항목 5개 분량의 최대 높이와 `overflow-y-auto`를 주고, 긴 내용은 줄바꿈되게 한다. 검증: 기록 4개는 스크롤 없이 모두 보이고, 8개면 목록 영역 안에서만 스크롤되며 날짜와 입력칸은 그대로 화면에 남는다. 100자짜리 항목이 영역 밖으로 넘치지 않는다.
