# Spec Delta

## ADDED Requirements

### Requirement: 기록 수정 시작
시스템은 목록의 각 기록에 [수정] 버튼을 보여주고, 누르면 그 항목 자리에 기존 내용이 채워진 수정 입력칸과 [저장]·[취소] 버튼을 보여줘야 한다(SHALL). 수정 입력칸에는 바로 포커스가 간다. 한 번에 하나의 기록만 수정 상태가 될 수 있다.

#### Scenario: 수정 버튼을 누른다
- **GIVEN** 목록에 "커피 마심" 기록이 있다
- **WHEN** 사용자가 그 항목의 [수정]을 누른다
- **THEN** 그 항목 자리에 "커피 마심"이 들어 있는 입력칸과 [저장]·[취소] 버튼이 보인다
- **AND** 입력칸에 포커스가 있다
- **AND** 그 항목의 날짜·시각은 그대로 보인다

#### Scenario: 다른 기록을 수정하던 중 또 수정을 누른다
- **GIVEN** "책 읽음" 기록을 수정 중이고 입력칸 내용을 "책 읽음 2"로 바꿨지만 저장하지 않았다
- **WHEN** 사용자가 "커피 마심" 항목의 [수정]을 누른다
- **THEN** "책 읽음" 수정은 저장되지 않고 취소된다
- **AND** "커피 마심" 항목이 수정 상태가 된다

### Requirement: 수정 저장
시스템은 수정 입력칸의 내용을 [저장] 버튼이나 Enter 키로 저장해야 한다(SHALL). 앞뒤 공백을 제거한 내용으로 기록을 바꾸고, 처음 저장한 날짜·시각은 바꾸지 않으며, 수정한 순간의 로컬 날짜·시각을 수정 시각으로 따로 기록한다. 저장 후 수정 상태가 끝나고 목록에서 기록의 위치는 그대로다. 한글 조합 중 Enter는 저장하지 않는다.

#### Scenario: 저장 버튼으로 수정한다
- **GIVEN** 2026-11-13 11:30에 쓴 "책 읽음" 기록을 수정 중이다
- **WHEN** 사용자가 내용을 "  책 30쪽 읽음 "으로 바꾸고 [저장]을 누른다
- **THEN** 그 기록의 내용은 "책 30쪽 읽음"이 된다
- **AND** 날짜·시각은 `2026-11-13 11:30` 그대로 보인다
- **AND** 목록에서 그 기록의 위치는 바뀌지 않는다

#### Scenario: Enter 키로 수정한다
- **GIVEN** 기록을 수정 중이다
- **WHEN** 사용자가 내용을 바꾸고 Enter 키를 누른다
- **THEN** [저장]을 누른 것과 같이 저장되고 수정 상태가 끝난다

#### Scenario: 한글 조합 중 Enter는 저장하지 않는다
- **GIVEN** 기록을 수정 중이고 마지막 한글 글자가 아직 조합 중이다
- **WHEN** 조합을 끝내려고 Enter 키를 누른다
- **THEN** 저장되지 않고 수정 상태가 유지된다

#### Scenario: 내용을 바꾸지 않고 저장한다
- **GIVEN** "커피 마심" 기록을 수정 중이다
- **WHEN** 내용을 바꾸지 않고 [저장]을 누른다
- **THEN** 수정 상태가 끝난다
- **AND** 그 기록은 수정된 기록으로 표시되지 않는다

#### Scenario: 수정한 내용이 새로고침 후에도 남는다
- **GIVEN** "책 읽음"을 "책 30쪽 읽음"으로 수정했다
- **WHEN** 사용자가 페이지를 새로고침한다
- **THEN** 목록에 "책 30쪽 읽음"과 `(수정됨)` 표시가 그대로 보인다

### Requirement: 수정 취소
시스템은 [취소] 버튼이나 수정 입력칸에서의 Esc 키로 수정을 취소해야 한다(SHALL). 취소하면 입력한 내용은 버리고 기록은 수정 전 그대로 보인다.

#### Scenario: 취소 버튼을 누른다
- **GIVEN** "커피 마심" 기록을 수정 중이고 내용을 "녹차 마심"으로 바꿨다
- **WHEN** 사용자가 [취소]를 누른다
- **THEN** 수정 상태가 끝나고 기록은 "커피 마심"으로 보인다

#### Scenario: Esc 키를 누른다
- **GIVEN** 기록을 수정 중이다
- **WHEN** 사용자가 수정 입력칸에서 Esc 키를 누른다
- **THEN** [취소]를 누른 것과 같이 수정이 취소된다

### Requirement: 빈 수정 거부
시스템은 수정 내용이 비어 있거나 공백만 있으면 저장하지 않고 "내용을 입력해주세요." 경고 알림을 띄워야 한다(SHALL). 기록은 바뀌지 않고, 알림을 닫으면 수정 상태가 유지되며 수정 입력칸에 포커스가 돌아온다.

#### Scenario: 내용을 모두 지우고 저장한다
- **GIVEN** "커피 마심" 기록을 수정 중이다
- **WHEN** 사용자가 내용을 모두 지우고 [저장]을 누른다
- **THEN** "내용을 입력해주세요." 경고 알림이 뜬다
- **AND** 기록은 "커피 마심" 그대로 저장되어 있다
- **AND** 알림을 닫으면 수정 입력칸에 포커스가 있고 수정 상태가 유지된다

#### Scenario: 공백만 남기고 Enter를 누른다
- **GIVEN** 기록을 수정 중이다
- **WHEN** 사용자가 내용을 공백 두 칸으로 바꾸고 Enter 키를 누른다
- **THEN** "내용을 입력해주세요." 경고 알림이 뜨고 기록은 바뀌지 않는다

### Requirement: 수정 입력 길이 제한
시스템은 수정 입력칸에 100자를 넘게 입력할 수 없게 해야 한다(SHALL).

#### Scenario: 100자를 넘게 입력하려 한다
- **GIVEN** 수정 입력칸에 이미 100자가 들어 있다
- **WHEN** 사용자가 글자를 더 입력한다
- **THEN** 수정 입력칸의 내용은 100자에서 더 늘어나지 않는다

### Requirement: 수정된 기록 표시
시스템은 내용이 수정된 기록의 날짜·시각 옆에 `(수정됨)`을 표시해야 한다(SHALL). 수정한 적이 없는 기록에는 표시하지 않는다.

#### Scenario: 수정한 기록과 수정하지 않은 기록
- **GIVEN** "책 읽음"은 수정했고 "커피 마심"은 수정하지 않았다
- **WHEN** 목록을 본다
- **THEN** "책 읽음" 항목에는 `(수정됨)`이 보인다
- **AND** "커피 마심" 항목에는 `(수정됨)`이 보이지 않는다

#### Scenario: 이전 버전에서 저장한 기록
- **GIVEN** 수정 기능이 생기기 전에 저장한 기록이 있다
- **WHEN** 사용자가 페이지를 연다
- **THEN** 그 기록들은 오류 없이 수정되지 않은 기록으로 보이고 [수정]할 수 있다

### Requirement: 수정 중 새 기록 저장
시스템은 기록을 수정하는 도중 위쪽 입력칸으로 새 기록을 저장해도, 수정 중인 항목과 그 입력칸에 적던 내용을 그대로 유지해야 한다(SHALL).

#### Scenario: 수정 중에 새 기록을 저장한다
- **GIVEN** "책 읽음" 기록을 수정 중이고 입력칸 내용을 "책 30쪽"까지 바꿨다
- **WHEN** 사용자가 위쪽 입력칸에 "점심 먹음"을 적고 저장한다
- **THEN** 목록 맨 위에 "점심 먹음"이 추가된다
- **AND** "책 읽음" 항목은 여전히 수정 상태이고 입력칸에 "책 30쪽"이 남아 있다
