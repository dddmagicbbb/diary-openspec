# Proposal

## Why

지금은 저장한 기록을 고칠 방법이 없어서, 오타를 내거나 내용을 바꾸고 싶으면 새 기록을 하나 더 써야 한다. 목록에서 바로 고칠 수 있게 해 기록을 깔끔하게 유지하고, 고친 기록은 고쳤다는 사실이 보이게 한다.

## What Changes

- 목록의 각 기록에 [수정] 버튼을 둔다.
- [수정]을 누르면 그 항목 자리가 입력칸으로 바뀌고 [저장]·[취소] 버튼이 나온다. 입력칸에는 기존 내용이 들어 있다.
- 수정 입력칸에서 Enter는 저장, Esc는 취소다. 한글 조합 중 Enter는 저장하지 않는다.
- 저장하면 내용이 바뀌고, 처음 쓴 날짜·시각은 그대로 둔 채 수정 시각을 따로 기록한다. 고친 기록에는 `(수정됨)` 표시가 붙는다.
- 수정해도 목록 순서는 바뀌지 않는다.
- 빈 내용이나 공백만 남기고 저장하면 "내용을 입력해주세요." 경고를 띄우고 저장하지 않으며, 수정 상태를 유지한다.
- 수정 입력칸도 작성 입력칸과 같이 최대 100자이며, 앞뒤 공백을 제거해 저장한다.
- 한 번에 하나의 기록만 수정할 수 있다.

**범위 밖 (이번 change에서 하지 않음)**
- 기록 삭제
- 수정 이력(이전 내용) 보관, 되돌리기
- 저장 날짜·시각 변경

## Capabilities

### New Capabilities
- 없음

### Modified Capabilities
- `diary-entries`: 저장된 기록을 목록에서 바로 수정하는 요구사항과, 수정된 기록 표시 요구사항을 추가한다. 기존 요구사항은 바뀌지 않는다.

## Impact

- 수정 파일: `app.js`(수정 상태 관리, 수정 저장), `index.html`은 바뀌지 않을 수 있음(목록 항목은 스크립트로 그림).
- 데이터: 기존 기록 형식에 선택 필드 `updatedAt`이 추가된다. 이 필드가 없는 기존 기록은 수정되지 않은 기록으로 그대로 읽힌다. 기존 데이터를 옮기거나 변환할 필요 없음.
- `README.md`의 기능 설명에 수정 기능을 한 줄 추가한다.
