## 2. 수정 상태와 화면

- [x] 2.1 `editingId`·`editDraft` 상태를 두고, `renderList()`가 보기 줄에 [수정] 버튼(`data-action="edit"`)과 `updatedAt`이 있으면 `(수정됨)`을, 수정 중인 항목에는 `<form>` 안의 입력칸(`maxlength="100"`, 값은 `editDraft`)·[저장]·[취소](`data-action="cancel"`)를 그리게 한다. 검증: 각 항목 오른쪽에 [수정]이 보이고, 콘솔에서 `editingId`를 바꾸고 다시 그리면 그 항목만 수정 줄로 바뀐다.
- [x] 2.2 `#entry-list`에 `click` 위임을 걸어 [수정]을 누르면 그 기록으로 `editingId`·`editDraft`를 설정하고 다시 그린 뒤 수정 입력칸에 포커스(커서는 끝)를 준다. 수정 입력칸의 `input` 이벤트로 `editDraft`를 갱신한다. 검증: [수정]을 누르면 기존 내용이 든 입력칸에 커서가 있고, 다른 항목의 [수정]을 누르면 앞 수정은 저장되지 않고 새 항목이 수정 상태가 된다.

## 3. 저장과 취소

- [x] 3.1 수정 `<form>`의 `submit`을 처리한다. trim한 값이 비면 `alert(EMPTY_INPUT_MESSAGE)` 후 수정 입력칸에 포커스. 기존과 같으면 수정 상태만 끝냄. 다르면 `text`와 `updatedAt`을 바꿔 저장하고(실패 시 실패 알림 후 수정 상태 유지) 수정 상태를 끝낸 뒤 그 항목의 [수정]에 포커스. 검증: "  책 30쪽 읽음 "으로 저장하면 "책 30쪽 읽음 (수정됨)"으로 보이고 날짜·시각과 위치는 그대로이며 localStorage에 `updatedAt`이 생긴다. 바꾸지 않고 저장하면 `(수정됨)`이 붙지 않는다. 빈칸·공백만이면 경고가 뜨고 기록은 그대로, 수정 상태가 유지된다. 새로고침해도 수정 내용과 `(수정됨)`이 남는다.
- [x] 3.2 [취소] 클릭과 수정 입력칸의 Esc 키로 수정 상태를 끝내고 그 항목의 [수정]에 포커스를 준다. 검증: 내용을 바꾼 뒤 [취소]나 Esc를 누르면 원래 내용으로 보이고 저장 데이터도 바뀌지 않는다.
- [x] 3.3 수정 입력칸 `keydown`에서 1.2의 함수로 조합 중 Enter를 막는다. 검증: 조합 중 Enter 이벤트(`isComposing: true`)는 기본 동작이 막히고, 일반 Enter는 저장된다.
