# diary-entries Specification

## Purpose

사용자가 브라우저에서 하루의 일을 한 줄로 적어 저장하고, 저장한 기록을 최신순 목록으로 다시 볼 수 있게 한다.

## Requirements

### Requirement: 오늘 날짜 표시
시스템은 페이지를 열면 사용자 기기의 로컬 시간대 기준 오늘 날짜를 `YYYY-MM-DD` 형식으로 화면에 표시해야 한다(SHALL). 월과 일은 두 자리로 채운다.

#### Scenario: 페이지를 열면 오늘 날짜가 보인다
- **GIVEN** 사용자 기기의 로컬 날짜가 2026년 12월 31일이다
- **WHEN** 사용자가 페이지를 연다
- **THEN** 화면에 `2026-12-31`이 표시된다

#### Scenario: 한 자리 월과 일은 0으로 채운다
- **GIVEN** 사용자 기기의 로컬 날짜가 2026년 3월 5일이다
- **WHEN** 사용자가 페이지를 연다
- **THEN** 화면에 `2026-03-05`가 표시된다

#### Scenario: UTC가 아닌 로컬 날짜를 쓴다
- **GIVEN** 사용자 기기의 시간대가 UTC+9이고 로컬 시각이 2026-11-13 08:00이다(UTC로는 2026-11-12)
- **WHEN** 사용자가 페이지를 연다
- **THEN** 화면에 `2026-11-13`이 표시된다

### Requirement: 한 줄 기록 저장
시스템은 사용자가 입력칸에 적은 한 줄을 저장 버튼으로 저장할 수 있게 해야 한다(SHALL). 저장되는 기록에는 앞뒤 공백을 제거한 내용과 저장한 순간의 로컬 날짜·시각이 들어간다. 같은 날에도 여러 번 저장할 수 있고, 저장할 때마다 별도의 기록이 추가된다.

#### Scenario: 저장 버튼으로 기록을 추가한다
- **WHEN** 사용자가 입력칸에 "산책했다"를 적고 저장 버튼을 누른다
- **THEN** 내용이 "산책했다"이고 저장 시각이 기록된 새 기록이 추가된다
- **AND** 입력칸이 비워진다
- **AND** 목록 맨 위에 새 기록이 보인다

#### Scenario: 같은 날 여러 번 저장한다
- **GIVEN** 오늘 이미 기록 하나를 저장했다
- **WHEN** 사용자가 다른 내용을 적고 다시 저장한다
- **THEN** 기존 기록은 그대로 남고 새 기록이 하나 더 추가된다

#### Scenario: 앞뒤 공백은 제거하고 저장한다
- **WHEN** 사용자가 "  책 읽음  "을 적고 저장한다
- **THEN** 저장된 기록의 내용은 "책 읽음"이다

### Requirement: Enter 키로 저장
시스템은 입력칸에 포커스가 있을 때 Enter 키를 누르면 저장 버튼을 누른 것과 같이 동작해야 한다(SHALL).

#### Scenario: Enter 키로 저장한다
- **WHEN** 사용자가 입력칸에 "커피 마심"을 적고 Enter 키를 누른다
- **THEN** 저장 버튼을 누른 것과 같이 새 기록이 추가되고 입력칸이 비워진다

#### Scenario: 한글 조합 중 Enter는 저장하지 않는다
- **GIVEN** 사용자가 한글을 입력하고 있어 마지막 글자가 아직 조합 중이다
- **WHEN** 조합을 끝내려고 Enter 키를 누른다
- **THEN** 기록이 저장되지 않는다
- **AND** 다음 Enter 입력에서 저장된다

### Requirement: 빈 입력 거부
시스템은 내용이 비어 있거나 공백만 있으면 저장하지 않고 "내용을 입력해주세요." 경고 알림을 띄워야 한다(SHALL). 이때 기록 목록과 저장된 데이터는 바뀌지 않으며, 알림을 닫으면 입력칸에 포커스가 돌아온다.

#### Scenario: 빈 칸으로 저장을 누른다
- **GIVEN** 입력칸이 비어 있다
- **WHEN** 사용자가 저장 버튼을 누른다
- **THEN** "내용을 입력해주세요." 경고 알림이 뜬다
- **AND** 새 기록이 추가되지 않는다
- **AND** 알림을 닫으면 입력칸에 포커스가 있다

#### Scenario: 빈 칸에서 Enter를 누른다
- **GIVEN** 입력칸이 비어 있다
- **WHEN** 사용자가 Enter 키를 누른다
- **THEN** "내용을 입력해주세요." 경고 알림이 뜨고 새 기록이 추가되지 않는다

#### Scenario: 공백만 적고 저장을 누른다
- **WHEN** 사용자가 공백 세 칸만 적고 저장 버튼을 누른다
- **THEN** "내용을 입력해주세요." 경고 알림이 뜬다
- **AND** 새 기록이 추가되지 않는다

### Requirement: 입력 길이 제한
시스템은 입력칸에 100자를 넘게 입력할 수 없게 해야 한다(SHALL).

#### Scenario: 100자를 넘게 입력하려 한다
- **GIVEN** 입력칸에 이미 100자가 들어 있다
- **WHEN** 사용자가 글자를 더 입력한다
- **THEN** 입력칸의 내용은 100자에서 더 늘어나지 않는다

### Requirement: 기록 유지
시스템은 저장한 기록을 사용자의 브라우저에 보관해, 페이지를 새로고침하거나 브라우저를 다시 열어도 같은 기록을 보여줘야 한다(SHALL).

#### Scenario: 새로고침 후에도 기록이 남는다
- **GIVEN** 사용자가 기록 3개를 저장했다
- **WHEN** 사용자가 페이지를 새로고침한다
- **THEN** 목록에 같은 기록 3개가 같은 순서로 보인다

#### Scenario: 보관된 데이터가 손상되었다
- **GIVEN** 브라우저에 보관된 기록 데이터를 읽을 수 없다
- **WHEN** 사용자가 페이지를 연다
- **THEN** 페이지는 오류 없이 열리고 기록이 없는 상태로 보인다
- **AND** 사용자는 새 기록을 저장할 수 있다

### Requirement: 기록 목록 표시
시스템은 저장한 모든 기록을 최신순으로 목록에 보여줘야 한다(SHALL). 각 항목은 `YYYY-MM-DD HH:mm` 형식의 저장 날짜·시각(24시간제)과 내용을 함께 보여준다. 내용은 입력한 글자 그대로 보여주며 HTML로 해석하지 않는다.

#### Scenario: 최신 기록이 맨 위에 온다
- **GIVEN** 사용자가 "첫째", "둘째", "셋째" 순서로 저장했다
- **WHEN** 목록을 본다
- **THEN** 위에서부터 "셋째", "둘째", "첫째" 순서로 보인다

#### Scenario: 항목에 날짜와 시각이 함께 보인다
- **GIVEN** 사용자가 로컬 시각 2026-12-31 14:05에 "한 해 마무리"를 저장했다
- **WHEN** 목록을 본다
- **THEN** 그 항목은 `2026-12-31 14:05`와 "한 해 마무리"를 함께 보여준다

#### Scenario: 기록이 없을 때
- **GIVEN** 저장된 기록이 하나도 없다
- **WHEN** 사용자가 페이지를 연다
- **THEN** 목록 자리에 아직 기록이 없다는 안내 문구가 보인다

#### Scenario: HTML처럼 보이는 내용도 글자 그대로 보인다
- **WHEN** 사용자가 `<b>굵게</b>`를 적고 저장한다
- **THEN** 목록에는 굵은 글씨가 아니라 `<b>굵게</b>`라는 글자가 그대로 보인다

### Requirement: 목록 스크롤
시스템은 목록 영역의 높이를 기록 5개가 보이는 정도로 고정하고, 기록이 5개를 넘으면 페이지 전체가 아니라 목록 영역 안에서 스크롤되게 해야 한다(SHALL).

#### Scenario: 기록이 5개 이하
- **GIVEN** 저장된 기록이 4개다
- **WHEN** 목록을 본다
- **THEN** 4개가 모두 스크롤 없이 보인다

#### Scenario: 기록이 5개를 넘는다
- **GIVEN** 저장된 기록이 8개다
- **WHEN** 목록을 본다
- **THEN** 목록 영역에 최신 기록부터 5개 정도가 보인다
- **AND** 목록 영역 안에서 스크롤하면 나머지 3개를 볼 수 있다
- **AND** 날짜 표시와 입력칸은 스크롤해도 그대로 화면에 남는다
